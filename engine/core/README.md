# Universal Core — U1.1
First independent Rust library; no production Android integration. F2.2 remains
the Android baseline. See ../../docs/UNIVERSAL_ENGINE_REQUIREMENTS.md and the
distributed-read and evidence RFCs in docs/.

Read-only byte windows with u64 offsets, up to 1 MiB per window, cumulative
per-session read budget, cooperative cancellation at bounded I/O chunks,
explicit errors and no partial success. No external dependencies, unsafe code,
network access, execution, extraction, signing or publishing. Caller provides
an authorized stable source; a path, snapshot, hash or report evidence ID is
not inferred. The window is an input-relative range for future evidence records.
Blocking OS I/O cannot be interrupted by the flag; it is checked between reads.
Budget counts admitted requests even on failure; caller-retained data and total
parallel budgets are not yet managed. No parser, desktop GUI, JNI, SAF bridge,
hash attestation, or scheduler yet.

Tests: cargo +1.85.1 test --locked --offline. Dedicated CI for Linux, Windows
and macOS. Tests use synthetic inputs, a virtual >4 GiB source and a temporary
small file; they do not prove throughput on real multi-GB files or Android.
Future stages: evidence identity and stable source attestation, format probing,
range adapters for archive entries, global scheduler and resource budgets.

## U1.2 candidate — SHA-256 observations
Stream the declared source or one range through the pinned RustCrypto sha2
library, consuming the existing session read budget. No custom cryptography.
The digest describes the bytes actually observed; mutable sources still require
snapshot/attestation policy. A range alone does not prove membership in a
previous full hash. No paths or secrets are exported in this milestone.
Seven additional tests, including standard vectors, chunk boundaries, errors,
cancellation, and range coordinates. The Cargo.lock generated by Linux CI is committed; fetch locked dependencies
and test offline with the same lock on all three operating systems before integration. U1.1's no-dependencies statement describes U1.1 only.

## U1.3 candidate — bounded format hints
Magic-byte triage reads at most 512 prefix bytes and four extra PE signature bytes. No extension-based inference, archive extraction or structural validation. ZIP/APK/JAR/MSIX, OLE/MSI, and ar/DEB remain unresolved container families; CAFEBABE is ambiguous. Ten new tests cover signatures, bounds, malformed pointers, budget, cancellation and truncation. Structural validation, parser capability registry, snapshot identity and provenance remain future work.

## U1.4 candidate — bounded source inventory
Logical source keys separate root scope, relative physical path and nested member paths. Deterministic ordering, duplicate rejection, bounded entry count/path payload, explicit coverage, and consistency between observed length and digest. No automatic filesystem traversal, extraction, absolute paths, SQLite, stable source attestation or report serialization. Logical paths are not safe extraction permissions; case and Unicode aliases are not resolved. Path payload budget does not measure total heap. Eight additional tests.
